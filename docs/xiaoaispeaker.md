# 小爱音箱

将 MoviePilot 可读的本地音乐推送到小爱音箱，提供播放台、歌单与收藏、语音点歌、设备分组和定时任务。设备控制经小米云端完成，音乐由音箱通过插件签发的限时直链读取。

## 快速开始

### 准备条件

- 小米账号下已有小爱音箱，MoviePilot 能访问小米登录、设备控制和对话记录接口。
- 音乐目录已挂载进 MoviePilot，插件能读取文件；音箱能通过 HTTP 访问 MoviePilot。
- 需要现场转 MP3 时，MoviePilot 所在环境中有可用的 `ffmpeg`。

### 播放第一首

1. 安装插件，打开 **插件配置**。在页头状态菜单中打开 **启用插件** 和 **在「发现」显示侧栏入口**，点 **保存配置**。
2. 在 **账号与音箱** 中选择账号密码、扫码或 Cookie 票据登录。成功后选择默认音箱。
3. 在 **曲库与直链** 填写 **音乐库路径**，例如 `/media/music`；这是 MoviePilot 环境内的路径，**留空不继承宿主音乐目录**。
4. 填写音箱可达的 **外部访问地址**，例如 `http://192.168.1.10:3000`。此项留空才会沿用宿主 `APP_DOMAIN` 的第一个非空地址。
5. 保存后到侧栏 **音乐库** 浏览目录，先选一首 MP3 播放。在 **播放台** 检查音量、队列与播放状态。
6. 要使用语音、歌单或定时播放歌单，先确认曲库索引就绪；需要时在音乐库栏手动重建索引。

首次建议先验证手动播放，再开启语音监听。云端返回“受理”不等于设备实际解码出声；不响时按[排查](#排查)区分地址、格式和播放接口。

## 登录

### 三种方式

| 方式 | 操作 | 注意事项 |
| --- | --- | --- |
| 账号密码 | 输入小米账号和密码，点登录 | 先保存账号配置再登录；可能要求图形或短信/邮箱验证码 |
| 扫码 | 切到扫码标签，用米家/小米音箱 App 扫码并确认 | 页面驱动轮询，过期点换一张；关闭页面停止后续轮询 |
| Cookie 票据 | 输入 `userId` 与 `passToken` 的值 | 从 `account.xiaomi.com` 获取，不粘贴整串 Cookie |

登录成功会刷新设备列表。默认设备优先级为：请求显式指定 → 配置的默认音箱 → 第一台在线设备 → 列表第一台。已配置的默认音箱若不在当前账号列表里，会报出原因，不自动换到其它设备。

### 验证码与票据

- **图形验证码：**按页面图片填写，继续当前登录会话。
- **短信/邮箱验证码：**插件会向小米请求发送；填写后提交，收不到可点重发。重发会重新建立发码流程。
- **扫码：**二维码有效期使用小米返回的时限，单次长轮询最多等待约 8 秒。扫码确认后用 `passToken` 换取 Mina 的服务票据。
- **Cookie：**先在浏览器登录 `https://account.xiaomi.com`，仅复制 `userId` 和 `passToken` 两个值。其它域的 `serviceToken` 不能代替它们。插件实际换票成功才认定登录成功。
- **静默续期：**服务票据过期时使用保存的 `passToken` 续期；失败后按当前登录方式重新登录。

账号在状态接口中回显掩码；密码和票据不回显。退出登录清除本机登录票据、最近播放记录、内存登录会话并清空队列，但不等于删除已保存的账号配置、收藏或其它插件数据。

<details>
<summary>登录协议与常见失败码</summary>

- 小米 `deviceId` 首次生成后持久化；扫码换票若带回设备标识，则保留该登录会话的值。反复生成新标识容易触发新设备校验。
- `serviceToken` 取登录重定向链最后一跳实际下发的 Cookie，不使用其它服务留下的同名值。
- 二次校验流程涉及 `/identity/list`、`verifyPhone` / `verifyEmail`；手机流程还需 `sendPhoneTicket`。仅收到 `notificationUrl` 不代表验证码已经发出。
- `code=70016` 表示小米未接受这次换票。检查 `passToken` 的来源域、是否过期以及是否属于同一账号；仍失败可重新扫码。
- 浏览器手工票据与 App 扫码票据按不同客户端标识依次尝试换票，日志会记录成功/失败阶段。
- 二维码原始 `loginUrl` 留在服务端，前端获取二维码图片与状态；图片本身也属于本次登录材料。

</details>

## 配置项

读取配置使用 **GET `/status` 返回的 `config`**；保存使用 POST `/config`，更新实际传入且不为 `null` 的字段。未提供的字段保留，空串按各字段的规则处理。当前没有 GET `/config` 接口。

### 账号、入口与曲库

| 界面项 | 配置键 | 默认值 | 含义 |
| --- | --- | --- | --- |
| 启用插件 | `enabled` | 关 | 侧栏与周期服务的准入开关 |
| 显示侧栏入口 | `show_sidebar_nav` | 开 | 在「发现」投影页面 |
| 小米账号 / 密码 | `username` / `password` | 空 | 账号留空或传掩码不修改；密码留空保留原值 |
| 默认音箱 | `default_device_id` | 空 | 按设备优先级选择，可在账号栏取消默认 |
| 音乐库路径 | `music_dirs` | 空 | 一行一个目录；留空无库内播放范围 |
| 外部访问地址 | `base_url` | 空 | 空值使用宿主 `APP_DOMAIN`，多个地址取第一个 |
| 可播放扩展名 | `audio_exts` | 空 | 使用内置列表，可自定义扩展名 |
| 最多入库多少首 | `library_limit` | `10000` | 后端有效范围 200–100000，达到上限会标记截断 |
| 自动保鲜周期（分钟） | `library_refresh` | `60` | 0–1440；0 关闭周期刷新，首次建索引及按需刷新仍可发生 |

默认扩展名：`mp3`、`m4a`、`aac`、`flac`、`wav`、`ogg`、`oga`、`opus`、`wma`。进入白名单只表示可被插件处理，不保证每个音箱能直接解码。

### 播放与直链

| 界面项 | 配置键 | 默认值 | 含义 |
| --- | --- | --- | --- |
| 播放接口 | `play_mode` | `auto` | 按型号选接口；可强制为 `url` 或 `music` |
| 非 MP3 现场转 MP3 | `force_mp3` | 关 | `/stream` 使用 ffmpeg，原本是 MP3 时不转 |
| play_music audioID | `audio_id` | 空 | 空值使用内置音频标识 |
| 直链有效期（秒） | `stream_ttl` | `3600` | 有效范围 300–259200 |
| 播放前设置音量 | `default_volume` | `0` | 0 不调整；1–100 在推流成功后设置 |
| 队列自动连播 | `auto_next` | 开 | 周期巡检判断曲终并推进队列 |
| 播放时常亮 | `keep_light` | 关 | 调整推流类型，效果由型号决定 |
| 连播时播报下一曲 | `tts_announce` | 关 | 自动切歌前发送曲名 TTS，再推送下一曲；不在新歌起播后追加播报 |

配置 `play_mode` 是**设备播放接口**；播放台的顺序/循环/随机是**队列播放方式**，两者含义不同。

### 语音与 AI

| 界面项 | 配置键 | 默认值 | 含义 |
| --- | --- | --- | --- |
| 开启语音监听 | `voice_enabled` | 关 | 轮询小爱的对话记录 |
| 监听哪些音箱 | `voice_devices` | 空 | 设备 ID 列表；留空监听默认音箱 |
| 轮询间隔（秒） | `voice_poll` | `2` | 后端范围 1–30，界面建议 2–30；间隔从本轮结束起算 |
| 命中前先打断音箱 | `voice_interrupt` | 开 | 已匹配且会抢占声道的动作执行前打断 |
| 搜索期间提示语 | `voice_hint_tts` / `voice_hint_text` | 关 / 正在搜索，请稍候 | 搜索类动作的 TTS 反馈；文字留空回默认 |
| 播报执行结果 | `voice_reply` | 开 | 未起播的操作结果或失败原因通过 TTS 回答；成功推流后不再播报确认 |
| 记住刚才那首 | `voice_memory` | 开 | 仅保存成功点歌的口令与路径，重复说同一句时优先重播 |
| 口令未命中交给 AI | `ai_enabled` | 关 | 使用宿主已配置的大模型解析意图 |
| 没命中当聊天 | `ai_chat` | 关 | 需同时开启 AI 并配置宿主模型 |
| AI 超时（秒） | `ai_timeout` | `6` | 2–30，限制每次模型调用的总等待时间，包含初始化、推理与清理；意图解析和聊天分别计时 |

`ai_ready`、`ai_provider`、`ai_model`、`ai_message` 是宿主模型的状态读数，不是独立配置。插件不另存一套模型 key 或端点。

口令表、分组和任务定义分别通过 `/commands`、`/groups`、`/tasks` 管理，不属于以上配置快照。

## 播放与曲库

### 播放接口与格式

1. 通常先用 `auto`。命中型号白名单时走 `player_play_music`，否则走 `player_play_url`。
2. 推流受理但无声时，先用 MP3 验证，再切换播放接口。
3. 库中主要是 M4A/FLAC 且设备无法直接播放时，可开启 `force_mp3`。

`player_play_music` 仍然携带插件提供的音乐 URL，不表示改播小米在线曲库。

现场转码的边界：

- 由 MoviePilot 环境中的 ffmpeg 按连接转为 MP3，不经过 Emby/Jellyfin 转码。
- 转码长度未知，不支持 Range 拖动；响应为 `Accept-Ranges: none`。
- 没有 ffmpeg 时提示并回落到源格式；ffmpeg 启动失败返回明确错误。
- 原格式传输支持 Range；`bytes=0-` 也按 206 返回。状态码不能替代实际播放验证。

### 目录浏览与索引

| 功能 | 数据来源 | 特点 |
| --- | --- | --- |
| 目录浏览 / 文件名搜索 | 实时文件系统 | 浏览有条数上限，搜索最多 6 层、默认 100 条 |
| 语音选曲 / 歌单 / 定时播歌单 | 内存曲库索引 | 标签与目录名参与匹配，支持繁简、拼音与模糊查找 |
| 标签缓存 | `library-tags.json.gz` | 按文件指纹减少重复标签读取 |

索引未就绪时语音选曲会提示重建；特定未命中路径可触发后台刷新，但不会在同一请求里等待整库重建并重试播放。刷新完成后再尝试口令。

目录和 `.m3u/.m3u8` 可形成歌单：目录歌单至少两首，单个歌单最多 2000 首；歌单来源发现有三层深度限制。m3u 只收录已进入本地索引的曲目，不将其中的远程 URL 当下载任务。

### 队列与睡眠定时

| 播放方式 | 行为 |
| --- | --- |
| 顺序播放 `order` | 队列末尾停止 |
| 列表循环 `loop` | 队尾回到第一首 |
| 随机播放 `random` | 记录已播位置，优先未播曲目 |
| 单曲循环 `single` | 重播当前曲目 |
| 只播这一首 `single_play` | 当前曲结束后停止推进 |

换队列保留播放方式：

- 页面或 `/play` 直接点一个文件，替换为单项队列；外部直链清空库内队列，结束后不接回旧歌单。
- 语音点歌重建同目录、同专辑队列；“播放歌手”取当前索引中的完整匹配集，不受搜索预览十条上限影响。专辑和歌手选曲按路径中的目录、碟号和音轨数字自然排序；m3u 歌单保留成员顺序。
- “加入队列”和展开歌单后的“歌单入队”只追加并去重，保留当前播放位置，不重播当前曲；空队列则从首个有效文件起播。“播放歌单”“整目录入队”和“播放收藏”替换当前队列并起播。
- 过滤失效或越库文件后，以实际播放路径定位队列高亮，不能沿用过滤前的序号。

连播由宿主约每 20 秒巡检一次，需本进程观察到本次推流 `status=1`、经过约 25 秒起播宽限，再连续两次看到 `status=0`，才推进下一首。`2` 表示暂停，`-1` 或读取失败表示未知，都不能建立“正在播放”的依据。OH2 的进度、时长和音频标识从嵌套播放详情读取。

巡检会核对设备、路径、队列会话与每次推流会话，丢弃切歌或控制前发起的旧查询结果。设备上报的音频 ID 或 URL 与插件推流不符时，暂停旧队列自动推进。没有音频身份的型号只能依靠本地会话与状态观察，无法识别所有官方播放；仅上报 `0` 的设备也仍可能把设备侧暂停与曲终混淆。

失败点歌、停止、已被设备接走的播报或识别到外部音频后，队列保留供查看，但不自动恢复；设备直接拒绝的播报不停用连播。明确“继续播放”会重新推送当前项，可能从头播放；切歌或重新点歌成功后恢复正常连播。普通暂停且直链仍在设备上时继续使用设备恢复操作。

睡眠定时支持 **按分钟** 或 **再播 N 首**，两者互斥；分钟上限 300，首数上限 500。按首数依赖连播巡检的曲终判定，需开启 `auto_next`。这是插件当前队列的一份状态，不是每台音箱独立的闹钟。

### 歌词

优先读取同目录 `.lrc` / `.txt`，也识别 `歌名.mp3.lrc`，再尝试音频内嵌歌词。支持常见中文编码与多时间戳 LRC；无时间戳的歌词按纯文本展示。歌词侧车文件需位于库范围内。

本插件显示已有歌词，不联网刮取歌词，也不向触屏音箱的本机界面投送歌词。需要补标签/歌词时可使用 [TagFlow](tagflow.md)。

## 语音控制

### 从对话到播放

```text
小爱完成语音识别 → 插件轮询对话记录 → 去重与时间基线 → 口令表 / 记忆 / AI
                                                         └─ 选曲与执行 → 音箱控制 / TTS
```

插件读取的是小米已生成的对话文本，不录制麦克风。部分型号使用 ubus `nlp_result_get`，其余走对话接口；可用性取决于型号和云端接口。

**启动首轮只建立基线，不执行历史口令。** 保存配置重置监听或更换设备后也会重新建立基线；对话仍可出现在最近记录中，但不会被重放。

监听区分“读取失败”“没有新话”“有新话”；失败时退避，最长 30 秒。成功轮清除旧错误并恢复配置间隔，空闲不额外加倍。间隔从本轮结束起算，同一监听器不并发读取。

AI 判定在独立 worker 中执行，监听无需等模型返回就可继续接收停止等确定性口令。每实例最多一个底层模型调用；超时或取消后若第三方还未完成清理，新 AI 调用会提示忙，不累积后台线程。新口令、播放、控制、配置重载或停用会使旧 AI 结果失效，晚到结果不播放、不播报、不写记忆。

### 常用口令

| 例句 | 作用 |
| --- | --- |
| 播放歌曲 稻香 | 在曲库中选曲 |
| 播放儿歌 小跳蛙 / 放儿歌 小跳蛙 | 明确的库内点歌口令，无需 AI；曲库中需有该歌曲 |
| 播放歌手 周杰伦 | 播放该歌手的匹配曲目 |
| 播放歌单 范特西 | 播放索引中的歌单 |
| 下一首 / 上一首 / 播放第 3 首 | 操作当前队列 |
| 继续播放 / 停止播放 | 控制音箱 |
| 音量调到 30 / 大声一点 | 设定音量或按步长调整 |
| 随机播放 / 单曲循环 | 修改队列播放方式 |
| 30 分钟后停止播放 | 设置睡眠定时 |
| 取消定时 / 还有多久停 | 取消或查询定时 |
| 收藏这首歌 / 这是什么歌 | 收藏或查询当前曲目 |

只有点歌、切曲、停止、播报等占用声道的动作才在配置允许时先打断。修改音量、播放方式、收藏和定时不会先执行 pause+stop。打断失败会记录设备回执；云端记录只能在小爱识别并生成记录后读取，因此不能保证抢在官方回复的第一个字前接管。成功起播后不追加确认 TTS，避免再次抢占新歌。

### 自定义口令与 AI

在 **插件配置 → 语音口令表** 可关闭类型、隐藏个别内置词或添加自己的说法。自定义词最多 60 条，每条最多 20 字；与内置表共同按最长关键词匹配。

例如新增“播放周杰伦”时，应选择明确的动作类型并填写默认内容“周杰伦”。用户说完整句后还有尾随内容时优先使用尾随内容，否则使用默认内容。用侧栏 **试一句话** 核对判定，默认只解析、不控制音箱。

判定顺序为口令表 → 记忆表 → AI。记忆映射保存于本机状态文件，最多 200 条、有效期 30 天；没有成功标记的旧记忆不参与重播，以免把历史失败点歌关联到上一首。AI 聊天上下文保留在进程内，约两分钟的活跃窗口仅用于状态展示，不影响正常轮询间隔。

AI 必须显式开启，并使用宿主「设定 → AI 大模型」的配置。试口令也走同一判定链，开启 AI 时可能调用模型。自定义口令只能使用现有动作类型；HTTP 端点和语音 AI 兜底不等于宿主助手/MCP 工具注册。

## 分组与定时任务

### 设备分组

在 **账号与音箱** 建组，至少两台音箱。同一设备只能属于一个组，移入新组会从旧组移除，旧组不足两台时失效。

播放、控制、音量与播报会带动组内设备；某台失败时返回对应原因。分组是云端指令分发，不提供帧级同步，起播存在时差。插件维护一份当前队列、播放方式与睡眠定时，不提供多组独立队列。

### 定时任务

配置页最多维护 50 条任务，侧栏负责启停、立即执行和查看最近 200 条执行日志。

| 规则 | 含义 |
| --- | --- |
| 每周 `weekly` | 勾选星期；这里 **0=周日**，与 TagFlow 的 cron 数字不同 |
| 每月 `monthly` | 选择 1–31 号；当月没有的日期不会触发 |
| 时间 | `HH:MM`，按 MoviePilot 进程本地时间判断 |
| 目标 | 默认设备、指定设备或全部设备；全部目标优先在线，均无在线状态时仍可能尝试缓存列表 |

动作包括播放歌单、从歌单中某首开始、停止、设置音量、设置播放方式、开启/关闭语音监听。播歌单依赖曲库索引；指定起始歌曲没找到时从第一首开始并记录说明。

任务由约 20 秒的周期巡检触发，正常完成的分钟级触发记录会落盘，防止普通重启后同一分钟重复执行。停机期间错过的时间不会补跑。当前没有法定节假日调休规则。

## 直链与数据存储

### 实际数据流

```text
MoviePilot ── 登录、设备控制、播放 URL、TTS ──> 小米云端 ── 指令 ──> 音箱
MoviePilot <──────────────────── HTTP 取流 ─────────────────────── 音箱
MoviePilot ── 可选的意图解析/聊天文本 ──> 宿主配置的大模型服务
```

签名直链不是加密文件名：URL 的 `k` 参数包含过期时间、签名和 **Base64URL 编码的库内路径**，该 URL 会经小米云端下发给音箱。账号/票据会用于向小米鉴权；开启 AI 时话语及相关聊天上下文会发送到宿主选择的模型服务。

音频由插件 HTTP 服务提供给请求方；转码在本机进行，不经过媒体服务器。不能据此表述为“路径和音频绝不离开本机”。

插件日志会记录文件名、设备、口令文本和故障信息；排查时只分享必要片段。

### 签名格式

```text
/api/v1/plugin/XiaoaiSpeaker/stream?k=<exp>.<sig>.<base64url(path)>
```

`/stream` 为匿名端点，校验有效期、HMAC 签名与库内真实路径及扩展名。签名使用 HMAC-SHA256 的前 32 位十六进制值。单参数设计用于避免小米云端改写多参数 URL 中的 `&`。

签名失败或过期时 HTTP 响应为“链接无效或已过期”，更具体原因写入插件日志；越库或非音频路径另有拒绝原因。直链应按临时访问凭据对待。

### 持久化数据

常见容器位置为 `/config/plugins/XiaoaiSpeaker/`，以宿主实际 `get_data_path()` 为准：

| 文件 | 内容 |
| --- | --- |
| `state/token.json`、`state/device_id.json` | 登录票据与小米设备身份 |
| `state/devices.json` | 设备列表缓存 |
| `state/secret.json` | 签名密钥，变化后旧直链失效 |
| `state/queue.json`、`state/last.json` | 当前队列与最近播放 |
| `state/favorites.json`、`state/sleep_timer.json` | 收藏与睡眠定时 |
| `state/voice_memory.json`、`state/voice_commands.json`、`state/voice_words.json` | 语音记忆、类型开关与自定义词 |
| `state/device_groups.json` | 分组 |
| `state/scheduled_tasks.json`、`state/schedule_logs.json`、`state/schedule_fired.json` | 任务定义、执行日志与去重记录 |
| `library-tags.json.gz` | 曲库标签缓存，可重建 |

状态文件与缓存以 0600 权限保存，普通配置由宿主管理。备份需覆盖宿主配置和插件数据目录；`plugins.v3/xiaoaispeaker/data/` 则是随源码分发的静态字表，不是运行数据目录。

## 接口与命令

路径相对于 `/api/v1/plugin/XiaoaiSpeaker`；独立实例以实际注册前缀为准。除 GET `/stream` 外均声明宿主 `bear` 认证，响应模型见 [`schemas.py`](../plugins.v3/xiaoaispeaker/schemas.py)。

### HTTP API

| 功能 | GET | POST |
| --- | --- | --- |
| 状态与配置 | `/status`（含 `config`） | `/config`（返回新状态） |
| 登录与设备 | `/devices` | `/login`、`/login/qrcode`、`/logout`、`/device/select` |
| 播放与控制 | — | `/play`、`/queue`、`/control`、`/volume`、`/tts`、`/mode` |
| 浏览与索引 | `/browse`、`/search`、`/library`、`/playlists`、`/playlist` | `/library/refresh` |
| 歌词、收藏、睡眠定时 | `/lyric`、`/favorites`、`/timer` | `/favorites`、`/timer` |
| 语音与口令 | `/voice`、`/commands` | `/voice/test`、`/commands` |
| 分组与任务 | `/groups`、`/tasks`、`/tasks/logs` | `/groups`、`/tasks`、`/tasks/run` |
| 音频流 | `/stream?k=…` | — |

常用请求示例：

```text
GET  /status
GET  /browse?path=%2Fmedia%2Fmusic
POST /play        {"path":"/media/music/艺人/专辑/01 - 曲名.mp3"}
POST /queue       {"paths":["/media/music/艺人/专辑/02 - 曲名.mp3"],"append":true}
POST /control     {"action":"pause"}
POST /volume      {"volume":30}
POST /voice/test  {"text":"播放歌曲 稻香","execute":false}
```

- `/play` 接受 `path`、外部 `url` 或文件名 `keyword`，按此优先级使用；可指定 `device_id`。
- `/queue` 的 `index` 与 `/control` 的数字动作使用 **0 起始**序号；语音“第 N 首”和页面显示使用 1 起始。
- `/queue` 的 `append` 默认 `false`，按 `index` 替换并起播；`append:true` 时忽略 `index`，服务端原子追加。非空队列保留当前设备与位置，显式指定不同设备会拒绝；空队列从首个有效文件起播。`paths` 为空或追加项全部无效时返回失败。
- `/voice/test` 默认仅判定；`execute:true` 使用与监听相同的打断、接管及成功记忆路径。判定期间若被新播放或控制取代，则不执行晚到结果。
- 账号密码登录可先 POST `/config` 保存，再 POST `/login` `{}`；验证码用 `{"code":"…"}`，重发用 `{"resend":true}`，Cookie 用 `{"user_id":"…","pass_token":"…"}`。
- `/login/qrcode` 的 `action=start` 取二维码，`action=poll` 查结果；后续轮询可能不带图片。
- `/commands` 的 `enabled`、`add`、`remove`、`hide`、`unhide`、`reset` 只更新对应部分；类型开关不影响内置停止兜底词。
- `/config` 未提供或为 `null` 的字段保留；某些字段的空串具有“清空/回默认”语义，账号密码例外见配置表。

宿主注入的前端 `api.get/post` 直接返回响应体。GET 查询条件需要编码到 URL，项目中的 `useApi.get(path, params)` 已封装该步骤。

### 远程命令

| 命令 | 作用 |
| --- | --- |
| `/xiaoai_status` | 查看登录、设备与播放状态 |
| `/xiaoai_play <关键词或库内绝对路径>` | 播放音乐 |
| `/xiaoai_control play\|pause\|stop\|next\|prev\|<序号>` | 控制播放；数字序号同接口，从 0 开始 |
| `/xiaoai_volume 0-100` | 设置音量，0 表示静音 |
| `/xiaoai_tts <文本>` | 播报文字 |

命令参数读取宿主 `arg_str`。配置中的默认音量 `0=不改动`，与音量命令的 `0=静音` 不同。

## 排查

| 现象 | 检查与处理 |
| --- | --- |
| 侧栏没有入口 | 在插件配置页打开 `enabled` 与 `show_sidebar_nav` 并保存 |
| 音乐库空白 | 确认 `music_dirs` 已填、容器挂载可读、扩展名被接受；没有宿主路径自动回落 |
| 登录失败 | 看具体阶段与小米返回码，验证码需续同次会话；票据无效时重新登录 |
| 登录成功但无音箱 | 刷新设备，确认账号归属与票据是否有效 |
| 推流成功但无声 | 查日志有无 `/stream 请求进来`：没有先查网络/地址，有请求再查接口/格式 |
| 音箱将音乐当电台或不解码 | 切换 `url/music`，先试 MP3，必要时开启现场转码 |
| 直链返回 403 | 查过期、签名密钥是否变化、路径及扩展名是否仍允许 |
| 重载后需反复登录 | 确认插件数据目录在持久卷上，状态文件可读写 |
| 手动能播，语音找不到 | 浏览与索引是两条链路，重建索引后用明确口令重试 |
| 口令不响应或变慢 | 看监听开关、设备列表、最近轮询时间、失败退避和云端对话接口；AI 日志区分超时、仍在清理和过期判定 |
| 点歌后跳回旧歌单 | 核对实际运行版本与队列更新请求；失败接管、停止和外部音频应暂停旧队列推进，“加入队列”应使用 `append:true` |
| 同句话判定不同 | 查看命中来源；AI 可能不确定，常用说法可加入自定义口令表 |
| 手按暂停后仍自动下一首 | `status=2` 按暂停处理；若型号只上报 `0` 则仍无法可靠区分曲终，使用插件暂停或关闭连播 |
| 定时任务没执行 | 核对时区、星期/日期、启用状态、索引与目标设备；停机错过时间不会补跑 |
| 歌词不显示 | 核对侧车文件名、编码与库内路径；没有现有歌词时插件不会联网补取 |
| 页面空白 | 核对插件根 `dist/assets/remoteEntry.js` 与引用分片是否同一构建 |
| 更新后接口仍是旧行为 | 按宿主实际安装与路由重绑机制验证，不能只看 `/status` 的版本值 |

### 不包含的能力

当前没有 MiIO/MIoT 本地 RPC、DLNA/UPnP 接收端、触屏音箱原生歌词投送、节假日调休规则或多房间帧级音频同步。
