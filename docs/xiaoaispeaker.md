# 小爱音箱 使用说明

插件目录 `plugins.v3/xiaoaispeaker/`，类名 `XiaoaiSpeaker`，配置前缀 `xiaoaispeaker_`。
把 MoviePilot 音乐库里的音频推到小爱音箱上听。这份文档讲怎么配、以及每处判据为什么
这么定；界面上的文案只留最短的一句，为的是把版面让给音箱与队列。

- 目录名 / 类名 / 配置前缀 / 各项键名从 v0.1 起没动过。改它们会让已存配置与插件数据
  一起失效（宿主按前缀存 `config_data`、按类名存 `plugindata`），更名只发生在展示层。
- 逐项变更历史看 `package.v3.json` 里本插件的 `history`；代码里那些「为什么这么写」
  直接写在对应常量的注释上，动代码前先读那几段。

---

## 它做什么、不做什么

做的：小米账号登录（三种方式）、曲库索引与文本匹配、本机签发限时直链推送到音箱、
侧栏运行视图（播放台 / 音乐库 / 歌单与收藏 / 定时任务 / 语音控制）、设备分组多房间同步、
睡眠定时、页面侧歌词、小爱对话监听驱动的语音口令，以及一组远程命令。播放地址由插件
本机签发，不经过媒体服务器转码。

刻意不做的四件事：

- **MiIO / MIoT RPC**。它只在个别触屏型号上用来走 `siid-aiid` 的 TTS action，普通
  `mibrain/text_to_speech` 已经能播报，而那条签名链路要额外的 xiaomiio serviceToken 与
  HMAC 细节，收益不抵复杂度。
- **DLNA / UPnP 接收端**。SSDP 组播与监听端口要在宿主容器里另开，第三方投送也无从认证；
  程序化投送的等价物是 `/play` 加 `/stream` 那对签名直链接口。
- **触屏音箱的本机歌词**。要设备侧 Music API 与那块 UI，页面侧歌词已覆盖同一需求。
- **法定节假日调休**。上游把 holiday-cn 数据集编进插件产物，装在宿主容器里的插件没有
  那份数据也没有更新渠道；要「只工作日 / 只周末」就分建两条任务勾不同周几。

## 安装与首次运行

1. 市场装好插件，在「插件配置」最上面把**启用插件**打开。这一项为什么必须做在插件自己
   这边：宿主投影侧栏入口前先调 `get_state()`，而这一项取的是插件配置里的 `enabled`；
   插件管理页那个开关写的是宿主自己的实例记录，插不进 `get_state()`。只在那儿打开，
   侧栏不会出现，周期任务也不会登记 —— 装好了但永远看不到入口的死结就是这么来的。
   保存时插件会顺带请宿主重建一次周期任务（`update_plugin_job`），不用重启主程序。
2. 第 1 步里登录小米账号（下一节三种方式任选其一），登成后音箱列表当场端出来，挑一台
   设为默认 —— 后端登录成功时已经强制刷过一遍设备，不需要再点「刷新设备」。
3. 第 2 步填**音乐库路径**（一行一个目录）与**外部访问地址**（音箱能访问到的 MP 地址）。
4. 侧栏「播放台」点一首试试。第一首不通，先看「排查」。

没登录、没取到音箱时第 2 步整个收起来（那些配置在拿到音箱之前改了也无从验证），但收起
来不能变成死路：「启用插件」与「显示侧栏入口」永远留在最上面可编辑，第 2 步旁边也给
一句「我知道，仍然直接编辑其他配置」。

## 登录

三种方式地位相同，任意一种登成都行；配好的票据只写进本机插件数据，接口永不回显。
登录入口只在「插件配置」的第 1 步出现一次。

### 一、账号密码

在配置页填账号密码点「登录」：**先保存再发起**。后端只认配置里那一份 —— 票据过期要
重登、语音轮询要换票，都从配置读，只在请求体里带一次等于没存。

登录在服务端跑小米那三步，换回 `serviceToken` / `passToken` / `userId`：

- `deviceId` 首次生成后就固定并存进插件数据，每次登录都复用。小米把它当设备标识，
  每登一次换一个新的，就等于每次都从「新设备」发起 —— 于是要么每次都要验证码，要么
  把已经存下的 `passToken` 判失效。
- `serviceToken` 取的是重定向链**最后一跳自己那条 Set-Cookie**，不是同名 cookie 的
  回落值。别的 `sid` 早就塞过一个同名 cookie，取错的那张票会一直 401，而且看起来
  像「密码错了」。

小米判定新设备或可疑登录时会停下来要验证码，页面按状态分支：

- `need_captcha`：回一张图形验证码，照图填进去提交。
- `need_verify`：小米往手机或邮箱发了码，把码填进来提交。这一跳的 `notificationUrl`
  可能是 `/fe/service/identity/authStart…`，插件会先 GET 同一个地址的 `/identity/list`
  变体把身份会话建起来，再 POST `verifyPhone` / `verifyEmail` —— 少这一步，码填什么都
  过不去。

**验证码要续跑在同一次进行中的会话里**（请求体只带 `code`），不是重新发起一次登录：
重新发起会让小米把上一次的努力全部作废，码也就永远对不上。

### 二、扫码

点「获取二维码」，页面列三种状态：等待扫码、成功、已过期。

- 二维码由 `sid=mijia` 的会话取回，有效期取小米给的 `timeout`（观察到 300 秒），页面
  挂倒计时条。**过期就点「换一张」**，旧码扫了也不会生效。
- 确认结果由页面驱动轮询：一次请求在插件侧最长挂 8 秒（小米的长轮询本来就挂着等），
  所以是串行问、不并发；页面一关就没有后续请求，插件不留没人收结果的后台循环。
- 单次非零 `code` 只当长轮询自己的重连抖动，连续两次才判过期 —— 一次就判死会把正在
  扫码的人赶走。客户端超时同样是常态而不是失败。
- 扫过并在手机上确认后，小米回 `passToken` / `userId`，插件拿它现换 `micoapi` 的
  serviceToken，`deviceId` 沿用扫码这一套（票据绑在设备标识上，中途换一个反而更像异常登录）。
- **二维码的内容（`loginUrl`）是一次性的登录凭证，只留在服务端，绝不回给前端** ——
  回出去等于谁拿到都能替本人把这次登录做完。
- 这条路不走密码，也就绕开了「新设备登录」那套风控；密码反复登不上时，同一个账号通常
  扫码能过。扫码不知道账号叫什么，票据里留 `userId` 供界面标出这是哪个账号。

### 三、Cookie 票据

前两种都不方便时的兜底：把浏览器里登录过小米账号的整串 cookie 粘进来。

- 先拿 `passToken` 现换一张活票。**换到了才说明这串 cookie 真的有效**；换不到才退回
  直接用粘进来的 `serviceToken`，并真跑一次 `device_list` 校验 —— 不通过就说清失败在
  哪一步，不假装登录成功。小米对坏票据只回 401，不会告诉你「你粘错了」。
- 解析吃了三个现实：名字大小写不定（`userId` / `userid` / `UserID`，统一按小写收），
  值常带 URL 转义（`%3D` 不解开就是张废票），偶尔被引号包住。粘 `deviceid=` 时用它，
  没有就复用本机那个固定的 `deviceId`。

### 过期、退出与隐私

- 状态里的 `token_expired` 只说明票据到期。续期是自动的（`passToken` 还在就能重铸
  `serviceToken`）；`refresh()` 失败时按登录方式给提示 —— 扫码登的会说「请重新扫码」，
  不会让你去找一个从来没填过的密码框。
- 「退出登录」清票据、清缓存的设备列表、清进行中的扫码会话。
- **账号在接口与页面上都只回掩码**（`13****34`、`ab***@example.com`，另有
  `username_set` 说明存没存过）：`/status` 每 5 秒把整份配置带回侧栏，明文账号名等于
  把手机号长期挂在任何能看到这块页面的人眼前。写回时带 `*` 的值一律当作「没改」，
  配置页那格也不预填掩码，免得一次保存把真账号覆盖成打不上的串。密码永不回显，只回
  `password_set`。
- `/login` 整段被包起来：小米那条链路上的任何异常都折成 `state=failed` 带一句能看懂的
  原因回给页面，原文进插件日志 —— 只回「登录失败」等于让人去猜是密码错、风控还是代码坏了。

### 登录失败怎么读

| 页面上的话 | 含义 | 下一步 |
| --- | --- | --- |
| `小米拒绝了本次登录：code=…，说明：…` | 账密不对或被风控挡下 | 核对账号；反复如此就改扫码 |
| 卡在图形验证码 / 二次校验 | 小米把它当新设备 | 照提示填码；填不过就改扫码 |
| `… 请重新扫码` | 扫码登的票过期了，且不能靠密码续 | 切到「扫码」重新来一次 |
| 小米云端业务鉴权失败（401/403） | 票据过期或粘来的 cookie 是死的 | 重新登录一次 |
| `云端受理但设备返回 code=…` | 登录没问题，是音箱侧拒了这条指令 | 看下一节「播放与接口选择」 |

## 播放与接口选择

- 播放接口两档：`player_play_url` 推签名直链；硬件码命中型号白名单的（`LX05` / `LX04`
  等一批较新的音箱）走 `player_play_music`。白名单判错时用 `play_mode="url"` 强制覆盖。
  设备行上标了「该型号需走 play_music，直链可能被当成电台播放」的就是命中白名单的。
- 控制 `player_play_operation`、音量 `player_set_volume`、播报 `text_to_speech`
  （失败回落 `player_play_tts`）。小米对同一句播报会返回设备码 `3012`，那被译成
  「可能已经播报」而不是报错。
- 目标设备优先级：显式传入 > 配置的默认音箱（默认音箱不在当前账号列表里时直接说明，
  而不是悄悄换一台）> 第一台在线 > 列表第一台。设备列表缓存 5 分钟，票据过期或网络失败
  时回落到缓存并带上失败原因。

## 限时直链的安全

`/stream` 是**匿名**端点（音箱带不上 MP 的登录态），权限靠三重判据：

1. HMAC-SHA256(`path|exp`) 的前 32 位十六进制摘要，用 `hmac.compare_digest` 常量时间比较；
2. 有效期（`stream_ttl`，默认 3600 秒）；
3. `realpath` 必须落在配置的库目录内。

支持 `Range` / 206。越库、过期、签名不对分别是明确的 403 文案，不笼统说「链接无效」——
要能分辨「地址填错了」和「这台音箱访问不到 MP」。签名密钥首次随机生成后留在本机，
换密钥会让已发出的链接失效（可接受，不做兼容层）。

库内路径与音频内容不出本机：只有签名直链的 URL 交给音箱。可播放范围由「音乐库路径」
与扩展名白名单限定，三处按同一条判据收敛（realpath 后必须落在库目录内、扩展名在名单里）：
`/stream` 走 `resolve_playable`，浏览与搜索本身就只从库根出发，所以不会出现
「列表里看得到、点下去 403」。

外部访问地址取主程序设置里的**第一个**域名：主程序那一项允许逗号分隔多个，而一条直链
只能有一个 host；host 里带空白的写法（`192.168.1.10 3000` 这类手误）直接判非法 ——
`urlparse` 不会报错，只会拼出音箱必然拉不到的地址。

## 曲库索引与文本匹配

`library.py` 一次扫盘把目录与 `.m3u` 收成「歌曲 / 歌单」两张表，落进插件数据并带标签
缓存做增量；没有标签就按文件名去掉序号推断，歌手从路径倒推。

文本匹配是归一化 + 中文数字等价 + 精确/等价/模糊三段打分，所以「播放周杰伦的稻香」
「歌单范特西」都能落到具体文件。未命中会按需触发一次索引重建再判一次，而不是直接回
「找不到」—— 但重建有最短 60 秒间隔，免得语音未命中变成扫盘循环。搜索限深 6 层、
命中 100 条就停：整库几万个文件时无脑 `rglob` 会先把请求拖死。

## 队列、定时与设备分组

- 连播交宿主 `IntervalTrigger(20s)` 托管，插件不自建调度器。判「播完了」要同时满足：
  起播已过 25 秒宽限，且**连续两次**读到停止 —— 起播初期云端会瞬时回一个 0 状态，
  单次判定会把队列一首一首烧掉。
- 播放方式五种（顺序 / 列表循环 / 随机 / 单曲循环 / 只播这一首）。随机进度记录已播过去
  重、播完一轮自动重来；换一批曲目只清进度不清方式（说过「随机播放」之后切歌单还是随机）。
- 睡眠定时能按分钟也能按首数；按首数是在「这一首真的播完」时判的，不是设个闹钟。
- 队列、播放状态、定时、索引、监听、分组一并搭在 `/status.extra` 里回来，页面一次轮询
  喂满所有栏，而不是一栏一发请求。
- 设备分组：一条指令带动全组（播放、切曲、暂停、停止、音量、播报），全组共用一份队列 /
  方式 / 定时；成员互斥 —— 把设备挪进新组会从旧组摘走，旧组不足两台即作废。组内某台
  离线只追一条「卧室：设备离线」的告警，不让整次操作判失败：音箱各自经云端收指令，没有
  帧级同步，轻微起播时差属正常。默认音箱所在的那一组即「全屋广播」的落点。
- 定时任务：`weekly` 按星期几（0=周日）、`monthly` 按几号，到点执行播歌单 / 从某首歌播 /
  停止 / 设音量 / 设播放方式 / 开关语音监听。触发挂在既有的 20 秒巡检上并按分钟去重，
  同一分钟不会双发；执行日志留最近 200 条，`POST /tasks/run` 不等到点就能验证这条任务
  真能跑起来。目标可以是全部在线音箱、几台指定音箱或默认音箱，已被同组带动的成员不再
  作为独立目标各下发一次。

## 语音控制

`speech.py` + `voice.py` + `intents.py`：读小米的对话记录（M01 这类走 ubus 的
`nlp_result_get`）把说的话变成命令。

轮询是**三态**的：`None` 表示没读到（不推进时间基线，下轮重来）、`[]` 表示读到了但没有
新话、列表才是真的有新话 —— 把「读失败」当成「没说过」会把我没听见的话当成我说过，
这是这套东西最容易做错的一处。监听器自带节流与失败退避（最长退到 30 秒），说过话之后
的对话窗口内保持满速，追问才接得上。

口令表逐类可开关，`POST /voice/test` 让任意一句话在**不接音箱**的情况下先看出会被判成
什么；执行覆盖点歌 / 歌手 / 专辑 / 歌单 / 收藏 / 随机 / 刚才那首 / 搜索 / 暂停 / 继续 /
停止 / 上下曲 / 按序号切曲 / 音量与加减 / 静音 / 播放方式 / 定时停止 / 取消定时 /
查定时 / 播报。

近几轮的问答留在本机做指代（「换一首」「就要这个」）。口令判不出来时可选把这句话交给
**主程序已经配好的那个智能助手**（`app.agent.llm.LLMHelper`，读「设定 → AI 大模型」的
provider/model/key/base_url）判意图，或开自由对话；插件不再另配一份端点与密钥，宿主没配
就在配置页写明缺哪一项并退回到只用口令表。两个方向都只在显式开启时发出网络请求，用完
把模型实例交还宿主（`close_llm`）。

## 远程命令

`/xiaoai_status`、`/xiaoai_play <曲名关键词 或 库内绝对路径>`、
`/xiaoai_control play|pause|stop|next|prev|<序号>`、`/xiaoai_volume 0-100`、
`/xiaoai_tts <文本>`。参数文本读宿主注入的 `arg_str`（不是 `arg`），失败也回一条消息
而不是把异常抛到消息渠道里。

## 页面

- 侧栏 Vue3 页面（`./AppPage`）只看运行，不看配置：运行总览 / 播放台 / 音乐库 /
  歌单与收藏 / 定时任务 / 语音控制六栏，状态 5 秒轮询、页面隐藏时停；详情页 `./Page`
  是同一批接口的紧凑版。
- 定时任务栏是只读列表加「启停 / 立即执行」两个对当下状态的动作，任务定义本身（时间、
  动作、目标音箱）只在配置页改；口令表同理。改配置一律走页头的「插件配置」按钮弹出的
  配置页，对话框打开期间侧栏停轮询、关掉立刻补一次刷新；配置页每次保存都往外抛
  `updated`，所以侧栏跟得上身后的改动，不会出现两处显示两个值。
- 配置页（`./Config`）按先后可用排成两步：第 1 步是登录 + 选默认音箱 + 设备分组，
  第 2 步才是播放行为、曲库、直链、语音、定时任务。
- `api.get` 只认第一个参数，`/browse`、`/search`、`/lyric`、`/playlist` 的条件由页面
  自己编码进 URL。配置页只发插件认识的字段（`/config` 缺省即保留原值）。
- 样式只写自己的类名与宿主 `--v-theme-*` 变量，深浅色都跟着主程序；构建的
  `.v-*` / `.mdi-*` 全局样式门禁一条不许命中。前端产物在 `dist/assets/`，与市场包
  一致才有效。

## 歌词

页面侧歌词：同目录 `.lrc` / `.txt` 优先，其次音频内嵌歌词标签；编码按
`utf-8-sig` / `gb18030` / `big5` / `utf-16` 依次试而不是假定 UTF-8，多时间戳行会展开，
`[ti:]` / `[ar:]` 这类头部不当歌词显示，没有时间戳的纯文本只做整篇展示。歌词文件软链到
库外时一律不读 —— `/lyric` 和 `/stream` 用的是同一条库内判据。

`GET /status`、`/devices`、`/browse`、`/search`、`/lyric`、`/timer`、`/favorites`、

## 排查

| 现象 | 先看 |
| --- | --- |
| 侧栏没有入口 | `enabled` 是否开着、`show_sidebar_nav` 是否关着；改过这两项要不要请宿主重建任务 |
| 登录一直失败 | 按上表读那句原因；账密反复不过就切扫码，别硬碰风控 |
| 登录成功但没有音箱 | 票据失效或账号名下确实没有音箱，点「刷新设备」重试 |
| 点了没声音 / 音箱当电台放 | 型号该走 `player_play_music`，把播放接口从 `auto` 改一下试 |
| 音箱拉不到直链（403/超时） | 外部访问地址是不是音箱可达的、`stream_ttl` 是否太短、路径是否在库内 |
| 语音口令不响应 | `voice_enabled`、监听设备是否包含这台、`/voice` 里 last_poll_at 有没有在动 |
| 直链播放到一半断 | 连播判定依赖 20 秒巡检 + 两次读到停止，宽限期内不会续播 |
| 页面空白 / 组件加载错误 | `dist/assets/` 是否与 `remoteEntry.js` 里的分片名一致、市场包是否完整 |
