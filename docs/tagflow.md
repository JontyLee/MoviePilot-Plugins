# TagFlow音乐库刮削

定时扫描音乐目录，从公开音乐平台检索元数据，沿用 MoviePilot 原生刮削链写入标签与封面，并提供逐文件核对、补齐和改写记录。

| 插件 ID / 主类 | `TagFlow` |
| 版本 / 宿主要求 | `1.0.0` / MoviePilot `≥ 3.1.6` |
| Release | [TagFlow v1.0.0](https://github.com/JontyLee/MoviePilot-Plugins/releases/tag/TagFlow_v1.0.0) |
| 源码 / 页面入口 | [`plugins.v3/tagflow/`](../plugins.v3/tagflow/) / 侧栏「整理」 |
| 配置前缀 | `musiclibraryscraper_` |

## 快速开始

1. 在插件配置中填写 **音乐库路径**，使用 MoviePilot 运行环境内的绝对路径，一行一个目录。Docker 部署填写容器挂载路径。
2. 首次先选一张专辑或一个歌手目录，保持 **只补缺**、**最低匹配分数 = 3**、**识别源留空**。
3. 打开 **启用插件** 与 **整理区侧栏入口**；勾选 **立即运行一次** 后保存。一次性开关提交后会自动复位。
4. 到侧栏「整理 → TagFlow音乐库刮削」查看结果。点文件行检查当前标签与实际改写，再决定是否扩大范围。
5. 需要定时维护时保留启用状态，默认每周日 `03:00` 扫描；在概览核对下一次实际执行时间。

推荐目录结构：

```text
/media/music/                 # 配置为音乐库路径
└── 艺人/
    └── 专辑 (2024)/
        ├── 01 - 曲名.flac
        └── 01 - 曲名.lrc
```

已有标签优先；缺失时才从库根以下的艺人、专辑目录和文件名推断身份。插件不会把库根本身的名称当作艺人或专辑。

> **写入前确认：**标签与封面直接写入音乐文件，插件没有撤销功能。自动扫描的「只补缺」还会叠加宿主音乐刮削策略；「重试」「立即刮削」「全量覆盖」使用覆盖写，详见[写入方式](#写入方式)。

### 运行条件

- MoviePilot 能读写所选音乐文件，并具备宿主音乐刮削与标签读取依赖。
- MoviePilot 能访问选中的音乐平台；无需部署 Music Tag Web，也无需配置它的地址、账号或密码。
- 扫描范围是宿主 `RMT_AUDIOEXT` 与插件支持列表的交集。实际扩展名可在配置页或 `/status.config.audio_extensions` 查看。
- `.trickplay` 缓存目录、排除路径以及指向库外的软链不会参与扫描，目录软链不递归跟随。

## 配置项

### 运行与范围

| 界面项 | 配置键 | 默认值 | 含义 |
| --- | --- | --- | --- |
| 启用插件 | `enabled` | 关 | 控制插件运行状态与周期服务 |
| 整理区侧栏入口 | `show_sidebar_nav` | 开 | 显示侧栏入口；需同时启用插件并具备管理权限 |
| 立即运行一次 | `onlyonce` | 关 | 保存后投递扫描，随后自动复位 |
| 执行周期 | `cron` | `0 3 * * sun` | 每周日 03:00；空值或非法值回落默认 |
| 音乐库路径 | `scraper_paths` | 空 | 一行一个库目录；留空不会扫描 |
| 排除路径 | `exclude_paths` | 空 | 从扫描范围中排除的目录 |

**星期按 APScheduler 解释：**`0=周一…6=周日`。插件只将星期字段单独的 `7` 转成 `sun`，其它数字不偏移。优先使用 `mon`、`sun` 等名字，并以界面回显的下次触发时间核对结果。

### 识别与写入

| 界面项 | 配置键 | 默认值 | 含义 |
| --- | --- | --- | --- |
| 写入模式 | `mode` | `""` | 只补缺；`force_all` 为强制覆盖 |
| 最低匹配分数 | `min_score` | `3` | 三项身份匹配的最低分，服务端限制为 1–3 |
| 识别源 | `resources` | `[]` | 留空使用全部内置源；点名后使用所选列表与顺序 |
| 识别源补歌词 | `fill_lyrics` | 关 | 选中候选缺歌词时，尝试从支持的源补取，再交宿主写入 |

- `resources` 留空会按空数组保存，不会被回写成固定的五个源，因此未来新增源仍可自动使用。
- `min_score` 小于 1 按 1，大于 3 按 3，无法解析时按默认 3；这是阈值收敛，不会得到“0 分也写”或“永远达不到 4 分”的模式。
- GET `/config` 回配置存储值；GET `/status` 回本轮生效值，例如展开后的源列表、`fill_empty` 模式名称。编辑配置应以前者为准。

## 数据页与补齐

### 四个视图

| 视图 | 内容 | 行操作 |
| --- | --- | --- |
| 已处理 | 已判定可跳过或已成功处理的文件 | 查看详情、编辑 |
| 有缺项 | 已处理账中 `missing` 非空的文件 | 查看详情、编辑 |
| 失败待重试 | 识别、阈值或写入失败，含重试超限项 | 查看详情、编辑、重试 |
| 待处理 | 当前库中尚未出现在已处理或失败账里的文件 | 查看详情、立即刮削 |

**有缺项是已处理的子集，四个数量不能直接相加。** 待处理桶不给编辑；有缺项行也没有「立即刮削」或「重试」按钮。

- 点任意文件行查看当前标签、缺项和改前 → 改后的差集。
- 已处理列表可筛选 **只看本插件改写**；只有存在实际改写记录的行才显示写入来源，其余显示 **未改写**。
- 分桶表头随内容变化：失败显示原因/分数，有缺项显示缺失字段，已处理显示写入来源。前端使用 `table-layout: fixed`，防止长路径挤压其它列。
- 流水线数字由本轮汇总折算，显示处理过程与统计，不代表每个文件正在某个节点执行的实时队列。

### 手工补齐一首歌

1. 在已处理、失败或有缺项视图点 **编辑**，等待文件现值载入。
2. 可以直接修改字段，也可以点 **获取候选**，比较各识别源给出的结果。
3. 点候选查看逐字段差异，选择要采纳的值；采纳只填表单，**保存后才写文件**。
4. 缺封面时填写图片 HTTP(S) 地址，或使用候选的 **采纳封面**。
5. 保存后重新核对文件详情与缺项。页面只提交真正改动的字段，空白文本不用于清空已有标签。

候选面板对每个源保留分数最高的一条，单次检索超时为 6 秒，同一路径短时间重开使用 60 秒缓存。人工检索不添加整库扫描的随机错峰，但仍受同源最短请求间隔约束。

支持编辑曲名、艺人、专辑、年份、音轨号和歌词。封面地址是独立的 `cover_url`，不属于文本字段：图片先下载，下载失败时整笔提交不写入；文本成功但内嵌封面失败时单独回报。历史最佳候选只保留摘要和“有无封面”，补封面需重新检索或手填地址。

### 自动重试缺项

自动增量判据只要求 **曲名、艺人、专辑、内嵌封面** 四项齐全；缺项检查还包括年份、音轨号和歌词。这两种“齐全”用途不同。

已处理账中仍有缺项且文件未变的条目，按 `_DEFICIENT_RETRY_DAYS = 30` 天重新尝试：

- 没有 `retry_ts` 的条目可在下一轮尝试；已有时间戳则等退避到期后的扫描。
- 没问出新值时仍留在已处理，不计入失败重试次数；识别源整体故障不启动这次退避计时。
- 补齐后恢复普通增量跳过；自动补齐仍遵循当前写入策略，不会因为缺项重试自行开启强制覆盖。

想立即补某一项，使用 **编辑 → 获取候选 → 保存**。若要让后端重新刮削指定文件，可以调用 POST `/retry`，但它是**覆盖写**，与退避后的自动补缺不同。

## 识别与写入规则

### 七步流程

```text
枚举音频 → 读本地身份 → 增量与重试判断 → 查询全部源 → 评分与选候选 → 宿主写入 → 记账
```

上图对应页面的七个环节。实现会先检查已有账本，命中未变且无需补缺的条目时，直接跳过标签读取和检索。

1. **枚举：**按库范围、扩展名交集与排除规则收集文件。
2. **身份：**优先读取已有标签，缺失项再用目录与文件名补足；本地曲名无法取得时不发检索请求。
3. **增量：**只补缺模式按 `mtime+size` 跳过未变文件，缺项到期重试和强制/定向处理例外。
4. **查询：**所有选中的源并行查询，不因某个源先得到满分而结束。自动扫描每源随机错峰 0–1.5 秒，同源至少间隔 0.6 秒。
5. **选择：**先比较匹配分数，同分比较完整度，再相同按配置源顺序及候选顺序取先出现者，不按网络返回先后选择。
6. **写入：**达到阈值后交给宿主音乐刮削链；没有的候选字段不会被拿来清空已有值。
7. **记账：**保存成功、失败、缺项与实际差集；定向任务的结果单列 `last_targeted`，不覆盖最近整库扫描的 `runs`。

### 评分与候选顺序

曲名、艺人、专辑各 1 分，归一化后互相包含即可命中。每项单独记录“对上”“未对上”“本地缺这项”。

| 最低分 | 准确含义 | 建议 |
| --- | --- | --- |
| `3` | 曲名、艺人、专辑全部命中 | 默认使用 |
| `2` | 三项中任意两项命中，不保证其中一定包含曲名 | 只在已核对的小范围降低 |
| `1` | 三项中任意一项命中，不等于只认曲名 | 自动写入容易误配，需逐条核对 |

**排序仍优先匹配分数。** 例如阈值为 2 时，3 分候选会优先于字段更多的 2 分候选；同为 3 分时再比较年份、音轨号、碟号与封面，每项非空计一次完整度。

失败原因中的“本地无曲名”表示无法构造检索身份，降低阈值不能补出这项信息。其它本地缺项也不会凭空得分，应先核对标签和目录结构。概览里的“最高分”是该失败原因组中某条记录的最高值，不代表降低阈值能修好整组文件。

### 写入方式

| 操作 | 增量账 | 覆盖已有标签 |
| --- | --- | --- |
| 只补缺模式的周期/一次性扫描 | 生效，含 30 天缺项退避例外 | 默认补空，仍受宿主策略影响 |
| 强制覆盖模式的扫描 | 忽略 | 是 |
| 页面「全量覆盖」/ POST `/scan` 的 `force=true` | 忽略 | 是 |
| 失败项「重试」、待处理「立即刮削」、POST `/retry` | 定向绕过 | 是 |
| 编辑保存 | 按明确提交的字段写入 | 只替换提交的非空字段；封面可替换 |

自动链可写曲名、艺人、专辑、专辑艺人、年份、音轨号、碟号、封面和歌词。最终标签/封面/歌词覆盖还要叠加宿主「设置 → 媒体刮削」的音乐策略，采用两边较强的一方。手工校对过的库应同时检查宿主配置。

歌词默认交给宿主 `LyricsChain`。当前额外歌词补取支持网易云和 QQ；打开 `fill_lyrics` 只增加候选的歌词来源，不保证每首取得歌词，也不替宿主决定是否覆盖。

### 失败与重试

| 结果 | 记账方式 | 后续动作 |
| --- | --- | --- |
| 本地无曲名、无候选、未达阈值 | 记文件失败，增加 `retries` | 核对身份或人工补齐 |
| 宿主写入失败 | 记文件失败 | 查权限、文件格式与宿主日志 |
| 全部源都未给出可解析响应 | 记服务故障，不增加文件失败次数 | 查网络或风控，稍后再扫 |
| 单文件处理抛异常 | 单列处理异常，保留原账 | 查具体异常，不伪装成识别失败 |
| 连续 5 个文件服务故障/处理异常 | 大于 5 个文件的批次中止 | 保留未处理部分，避免持续空打 |

正常文件失败最多自动累计 5 次；达到上限且文件 `mtime+size` 未变时跳过，手动重试或强制扫描可绕过上限。全部源中只要有一个成功返回可解析的空结果，本轮就不属于“所有源不可达”。

兼容导入的 `MTW 不可达`、`MTW 鉴权失败`、`MTW 接口报错`、`内置识别源不可达` 也按服务故障识别。

## 识别源

| 源标识 | 平台 | 主要字段 | 限制 |
| --- | --- | --- | --- |
| `netease` | 网易云 | 曲名、艺人、专辑、封面、年份、音轨、碟号 | 音轨为裸序号，不含专辑总曲数 |
| `qmusic` | QQ 音乐 | 曲名、艺人、专辑、封面、年份、音轨、碟号 | 封面按专辑 mid 构造 |
| `kugou` | 酷狗 | 曲名、艺人、专辑、封面、时长 | 当前检索响应不提供年份和音轨 |
| `migu` | 咪咕 | 曲名、艺人、专辑、封面、年份、时长 | 当前检索响应不提供音轨 |
| `musicbrainz` | MusicBrainz | 曲名、艺人、专辑、发行日期、时长、MBID | 当前检索不补封面和音轨 |

每个源最多取 10 条候选。音轨号目前主要依靠网易云和 QQ；若最佳候选来自其它源且没有音轨，需要手动编辑。文件名前的序号不直接作为自动写入的音轨号，以免把年份、碟号或卷号误当曲序。

## 接口与命令

以下路径相对于 `/api/v1/plugin/TagFlow`；宿主使用独立实例 ID 时，以实际注册前缀为准。普通接口声明 `auth="bear"`，外部调用需要宿主认可的认证。

这些是 **HTTP API 和事件命令**；能通过 HTTP 调用不代表已经注册为助手/MCP 工具。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/status` | 扫描状态、各类计数、生效配置、最近失败 |
| GET | `/files` | 分桶分页，`bucket=done/failed/pending/deficient`，支持 `limit`、`offset`、`search`；已处理可用 `written=1` |
| GET | `/file?path=…` | 当前标签、缺项与改写记录 |
| GET | `/candidates?path=…` | 各源最佳候选和失败账中的历史摘要 |
| GET | `/config` | 配置存储值，保留空数组等语义 |
| POST | `/config` | 部分更新配置，只改传入且受支持的键 |
| POST | `/scan` | 扫描库，`{"force":true}` 为全量覆盖 |
| POST | `/retry` | `{"paths":[…]}` 定向覆盖刮削；`{"bucket":"failed","all":true}` 重试全部失败项 |
| POST | `/edit` | 按 `path`、`fields`、可选 `cover_url` 编辑单文件 |

编辑请求示例：

```json
{
  "path": "/media/music/艺人/专辑/01 - 曲名.flac",
  "fields": {"year": "2024", "tracknumber": "1"},
  "cover_url": "https://example.com/cover.jpg"
}
```

将示例路径和图片地址替换为实际值。`accepted=true` 对扫描/重试只表示任务已接收；需继续查看运行状态与账本。编辑返回 `cover="failed"` 时表示文本可能已成功写入，但封面未成功内嵌。

远程命令保留原名称以兼容已有调用：

| 命令 | 作用 |
| --- | --- |
| `/music_scraper_status` | 状态、失败原因分布与下次扫描时间 |
| `/music_scraper_retry` | 重试全部失败项，按覆盖写投递 |

## 配置与数据管理

### 兼容配置来源

插件可以通过 `_migrate_legacy_identity()` 从 `MusicLibraryScraper` 身份导入配置和四本状态账。需要导入时，先安装并加载 TagFlow，核对配置与进度后再移除来源实例，避免提前删除待导入的数据。当前身份已有对应数据时不会重复导入。

`source_backend`、`mtw_base_url`、`mtw_username`、`mtw_password` 不用于连接服务；读取时兼容 `mtw_resource`，完整快照保存为 `resources`。这些是数据兼容约定，不需要在首次配置时填写。

### 状态账与备份

| 数据键 | 内容 |
| --- | --- |
| `done` | 已处理文件的指纹、缺项、来源及 `set` / `set_ts` 改写记录 |
| `failed` | 失败原因、次数、分数与当次最佳候选摘要 |
| `runs` | 最近一次整库扫描汇总 |
| `last_targeted` | 最近一次定向重试汇总 |

这些数据使用宿主插件数据接口保存；备份时覆盖宿主中的 TagFlow 配置与插件数据，并独立备份音乐文件。差集只保留部分字段和有无封面/歌词，不是可还原原文件的备份。

`done` 条目没有 `missing` 时，首次打开缺项视图会并行补查一次并落账；之后读取账本。扫描中间按时间间隔落账，完整结束时清理库中已消失的记录；提前停止或故障中止不会清理尚未走到的条目。

## 排查

插件日志中的 `[music-scraper]` 是保留的日志前缀，对应当前 TagFlow。

| 现象 | 检查与处理 |
| --- | --- |
| 侧栏没有入口 | 确认 `enabled` 与 `show_sidebar_nav` 开启，账号有管理权限，入口在「整理」 |
| 扫描数为 0 | 核对容器内路径、读写权限与 `audio_extensions` 交集 |
| 大量识别源不可达 | 查出网、平台风控或响应改版；此类故障不烧文件重试次数 |
| 一整片文件没有曲名 | 核对整轨音频、文件名及目录结构；先补身份或排除范围 |
| 有缺项长期不减少 | 查看 30 天退避；立即补齐走编辑，音轨/歌词可能是平台未提供 |
| 已处理很多，本插件改写很少 | 可能已有标签、宿主策略未写入，或导入记录没有差集；查看详情，勿把已处理数当改写数 |
| 失败显示重试超限 | 修正元数据或环境后手动重试；重试会覆盖写 |
| cron 不在预期周几运行 | 使用 `sun` 等名字，核对下次触发时间与宿主时区 |
| 页面空白或分片加载失败 | 检查插件根 `dist/assets/remoteEntry.js` 及其引用分片是否完整、来自同一构建 |
| 想恢复写入前的标签 | 使用文件备份或人工修正；只补缺不会撤销已经写入的值 |

## 数据流与源码职责

平台检索请求只发送清洗后的曲名/艺人关键词，不发送本地完整路径或目录树；自动写入时可能下载封面与歌词，不上传或下载音乐音频。日志和状态账会保存库内文件路径，排查时按需分享。

| 文件 | 职责 |
| --- | --- |
| [`__init__.py`](../plugins.v3/tagflow/__init__.py) | 插件生命周期、配置、扫描、评分、宿主写入、状态账与接口 |
| [`sources.py`](../plugins.v3/tagflow/sources.py) | 各平台请求描述与候选/歌词解析；实际网络请求由主模块执行 |
| [`frontend/src/components/Config.vue`](../plugins.v3/tagflow/frontend/src/components/Config.vue) | 配置表单与保存 |
| [`frontend/src/components/Page.vue`](../plugins.v3/tagflow/frontend/src/components/Page.vue) | 数据分桶、候选比较与编辑 |
| [`frontend/src/components/AppPage.vue`](../plugins.v3/tagflow/frontend/src/components/AppPage.vue) | 侧栏入口与配置对话框 |
| [`frontend/src/components/flow.ts`](../plugins.v3/tagflow/frontend/src/components/flow.ts) / [`FlowPipeline.vue`](../plugins.v3/tagflow/frontend/src/components/FlowPipeline.vue) | 共用流程描述、计数折算与可视化 |
| [`tests/v3/tagflow/test_tagflow.py`](../tests/v3/tagflow/test_tagflow.py) | 整插件离线回归 |
